# Sours

مستودع PHP يضم ملفات لبوت/أدوات Telegram لإدارة المجموعات. يتضمن المصدر عمليات إشراف وإدارة مثل الحظر والتقييد والاشتراك الإلزامي، ويتعامل مع Telegram عبر واجهة HTTP API ويستخدم ملفات JSON محلية. هذه خلاصة للشفرة الموجودة وليست تأكيدًا على اكتمال الوظائف أو صلاحيتها للاستخدام الإنتاجي.

## حالة المصدر وحدوده

- لا يحتوي جذر المستودع على README حالي.
- توجد نقطتا دخول PHP هما `i.php` و`carlos.php`، لكن لا توضح الملفات أيهما نقطة الدخول المقصودة أو كيف ترتبطان؛ لذلك لا يُفترض أنهما تطبيق واحد متكامل أو أن إحداهما بديل للأخرى.
- توجد إشارات إلى مجلدي `data/` و`bots/` وإلى ملف `admin.json`، لكن ملف إعداد آمن أو قالبًا له غير متاح في المستودع. لا يمكن تحديد إعداد الإدارة أو مسار تسجيل webhook كاملًا من الملفات المتاحة.
- ملفات JSON محلية؛ ولا يحدد المستودع سياسة الاحتفاظ أو آلية نسخ احتياطي أو تخزينًا دائمًا عند النشر. مجلدات Docker تُنشأ داخل صورة الحاوية، لكن إعداد تخزين دائم غير موجود.
- الأوامر أدناه مستندة إلى ملفات الإعداد، وهي **غير مجرّبة**. لم تُشغّل الشيفرة أو تُختبر.

## الميزات الظاهرة في المصدر

بحسب الملفات الموجودة، يتضمن المشروع:

- تكاملًا مع Telegram لتنفيذ طلبات البوت والتعامل مع تحديثاته.
- وظائف لإدارة المجموعات والإشراف عليها، بما في ذلك إجراءات الحظر والتقييد.
- آلية للاشتراك الإلزامي، وعمليات مرتبطة بـ webhook.
- تخزينًا محليًا باستخدام JSON.

لا يثبت وجود الملفات وحده أن جميع هذه الوظائف مكتملة أو موصولة بنقطة تشغيل واحدة؛ ولم تُتحقق سلوكياتها عمليًا.

## المتطلبات والإعداد

يحدد `Dockerfile` صورة PHP 8.2، ويثبت امتداد cURL الخاص بـ PHP. كما يحدد تشغيل خادم PHP المضمّن على المنفذ `8080`، وينشئ `data/` و`bots/` داخل صورة الحاوية. وملف `fly.toml` يشير إلى استخدام Docker والمنفذ الداخلي `8080` في إعداد Fly.io.

إذا كان Docker متاحًا، فالخطوات التالية تعكس ما يحدده `Dockerfile`، لكنها **غير مجرّبة**:

```sh
docker build -t sours .
docker run --rm -p 8080:8080 sours
```

يشغّل الملف خادم PHP المضمّن بربط `0.0.0.0:8080`. لا يُعد هذا إعدادًا آمنًا للإتاحة العامة. يجب عدم نشره على الإنترنت قبل مراجعة الشيفرة وتأمين الرمز والإعدادات، وتقييد الوصول، وتحديد طريقة موثوقة لتخزين البيانات. لا يشرح المستودع كيفية إعداد webhook أو استكمال إعداد الإدارة، لذا لا تُعد هذه الخطوات إعدادًا كاملًا للبوت.

## تنبيه أمني

يحتوي أحد ملفات المصدر على رمز Telegram مضمن. اعتبره مكشوفًا: أبطله/دوّره لدى Telegram قبل أي استخدام، ثم انقله إلى إعداد سري خارج الشيفرة وأزل النسخة المكشوفة من تاريخ المستودع وفق إجراء مناسب. لا تنسخ الرمز إلى ملفات التوثيق أو السجلات أو المستودع مجددًا.

تتعامل الوظائف الموصوفة مع صلاحيات إدارية وإجراءات قد تؤثر في أعضاء المجموعة. راجع الصلاحيات والتحقق من هوية المشرفين، ولا تمنح البوت إلا أقل صلاحيات لازمة. كما أن خادم PHP في الإعداد الحالي مربوط بكل واجهات الشبكة، وملفات JSON المحلية لا توفر بذاتها حماية أو تشفيرًا أو استمرارية. لا تستخدم إعداد Fly المذكور كدليل على جاهزية إنتاجية أو أمان النشر.

## التحقق

لم يُشغّل التطبيق أو Docker، ولم تُثبّت اعتماديات منفصلة أو تُنفذ اختبارات. لا توجد في الملفات التي تمت مراجعتها تعليمات اختبار أو تحقق تشغيلي مؤكدة.
